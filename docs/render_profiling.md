# Render profiling

`app.window.set_render_profiling(counters, timestamps)` configures profiling on the window thread. Counters default to enabled; timestamps default to disabled. `app.window.render_stats()` returns the last completed render's counters when called from an update callback. Both functions are main-thread bindings.

The counter frame number is independent of the simulation tick. Categories are `sprites`, `pending`, `shapes`, `lighting`, `materials`, `particles` and `other`. Each reports queue-buffer `writes`, uploaded `bytes`, direct/indexed/indirect `draws`, and dynamically `packed` sprite records. `cpu_ms` currently measures sprite preparation, pending batch preparation/encoding and shape draw preparation/encoding only; other categories have no CPU timer yet. Nested shape work is included in pending CPU time, so those times must not be added together as exclusive stages. Frame totals also expose `submits`, `tessellations` and dynamic sprite `buffer_growths`.

The scope is engine-owned operations routed through `render_profiler.h` during `Window::run_wgpu_render_pass`. Third-party ImGui uploads/draws, custom application GPU calls, uploads before the render scope (including static staging), and the profiler's own resolve submission are excluded. Do not label these counters total adapter traffic or total frame draws. New engine upload/draw paths should use the same wrappers. A failed surface acquisition does not start a new counter frame.

The window requests the optional timestamp feature when the adapter supports it. Profiling can still disable timestamp encoding at runtime. `gpu_supported` means the device feature is enabled; `gpu_enabled` means it is currently being sampled. Unsupported hardware continues with CPU/counter observations; CPU time is never reported as GPU time.

Timestamps cover instrumented render and compute passes. Three independent query/readback slots allow asynchronous results; a busy pool skips a sample. Each slot holds at most 64 pass pairs. `gpu_skipped_frames`, `gpu_dropped_passes` and `gpu_failed_readbacks` report cumulative omissions. Results carry their own `gpu_frame`, `gpu_valid` and ordered `gpu_passes` (`name`, `ms`). Pass names may repeat; ordinal and frame identify a sample. Timings may be quantized to zero. A last valid GPU result may be older than the CPU frame or survive disabling sampling; check `gpu_enabled` and deduplicate by `gpu_frame`.

Resolve/readback uses a separate submission after all pending batches. Its overhead is intentionally excluded from application-submit counters and must be measured separately. Mapping callbacks publish only atomic completion status; collection, mapped-range reads and unmapping happen on the window thread on a subsequent frame. No frame waits for its timestamp result. Callback state survives profiler teardown through shared ownership.

Counter/timestamp configuration does not select a different sprite order. The ordering contract is documented in [sprite_ordering.md](sprite_ordering.md). Dirty percentages, retained-cache hits and comprehensive allocation accounting belong to subsequent measurement work and must not be inferred from packed counts.
